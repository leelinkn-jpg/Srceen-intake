# 秒记中枢运行手册（模型无关）

## 固定原则

1. 五个项目可由用户选择任意支持本地文件读取的模型运行；规则不得绑定厂商或模型名称。
2. 四个领域项目只读本领域目录中的业务数据，只写本领域的`AI报告`、`状态`和`日志`。
3. 总管默认只读四个领域的完成报告，不重新扫描全部原始数据。
4. 原始数据永不由模型修改。报告建议必须经手机确认后才转为待办。
5. 正式输出必须同时具有 Markdown 与 JSON，JSON `status=complete` 后手机才读取。

## 周期

- 日报：工作、健康、成长；财务只引用最近周报或月报。
- 周报：工作周报在周日下午检测到周经营数据、渠道营销建议、周会提纲齐全后生成；财务、健康、成长周日22:00；综合周报周日22:15。
- 月报：四领域，月末22:00；综合月报22:15。
- 工作日晨报采用双触发：WHOOP就绪时触发；08:15仍未就绪则先发布缺少今日WHOOP的版本，后到数据触发同一`reportId`的新修订版。

## 执行顺序

1. 读取本项目`规则/RULES.md`、`规则/INPUTS.md`和对应任务模板。
2. 确认周期、数据截止时间和触发原因。
3. 只读取白名单内的必要文件，排除临时文件和未完成写入。
4. 生成领域 Markdown 与 JSON到本项目`状态/<周期>/`。
5. 写临时文件，校验成功后原子改名为正式文件。
6. 四领域互不阻塞；失败写入简短错误日志，不复制敏感正文。
7. 总管读取可用领域报告，明确列出缺失领域，发布唯一综合报告。

## 幂等、补跑和版本

- `reportId`由领域、周期类型和周期结束日期确定；相同输入不得重复生成。
- 输入变化时覆盖同名报告并增加`revision`，不得产生第二个逻辑报告。
- 锁文件位于`系统/锁`；进程异常退出后必须校验锁的进程是否仍存在。
- Mini休眠或离线导致错过时间时，唤醒后补跑未完成周期。
- 拒绝过的相同建议不得在下一轮原样重复；必须出现新证据或调整建议。

## 安全边界

- 不读取`.codex_tmp`、`.tmp_rebuild`、`node_modules`、渲染缓存、预览图、`~$`锁文件和`.DS_Store`。
- 不把完整原始数据复制到日志。
- 不进行医疗诊断；不把推断写成事实；不把转账算作收支。
- 不自行创建待办、改余额、改账本或删除原始资料。
