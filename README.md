# 秒记（Screen-intake）

同时按一下音量上+音量下键，直接读取当前屏幕上的文字内容，交给通义千问判断是账单 / 待办 / 灵感，自动分类写入本地文件。

## 工作流程

```
同时按下音量上 + 音量下键（差不多同时即可，不用刻意按久）
  → 无障碍服务识别出这是组合键：不弹音量条、不真的改变音量
  → 立刻震两短下 + 弹「已触发，识别中…」提示（这一步跟下面的识别结果反馈是分开的）
  → 直接读取当前屏幕的文字节点（不截图、不录屏）
  → 把文字（不是图片）发给通义千问文本模型（阿里云百炼）判断
  → 按返回的 type 分流，并再震一次表示结果：
      expense → 保存文件夹/账本.csv （一短震）
      todo    → 保存文件夹/待办.md （一短震）
      note    → 保存文件夹/灵感.md （一短震）
      ignore  → 不写入（两短震）
  → 失败或解析不出来 → 保存文件夹/待确认/时间戳.txt（原始文字 + 失败原因）（长震）
```

保存文件夹是用户在设置里用系统文件选择器（SAF）选定的一个目录，建议直接选
Syncthing / 坚果云等会自动同步到电脑的那个文件夹。

## 为什么是「音量上+下键」而不是长按单键 / Pixel 轻触背面

- 最早的方案是长按音量下键 0.5 秒：单键长按不消费按下事件，导致 Android 按住这段时间会
  按自身的自动重复逻辑持续调低音量，体验很差。
- Pixel 系统自带的「轻触背面」（Quick Tap）只能设成"打开某个 App"，没法直接调用 App 里的
  某个具体动作——选它只会把「秒记」整个界面打开，不会静默读屏，所以放弃了这条路，连带
  把之前给它准备的 App 快捷方式（`CaptureNowActivity` / `shortcuts.xml`）也一起删掉了：任何
  会打开新 Activity 的触发方式，本质上都会把"当前活跃窗口"切换成那个新 Activity，导致读到
  的是空内容而不是你原来那屏，这是无障碍读屏方案本身的限制，不是 Pixel 独有的问题。
- 改成"两个音量键差不多同时按下"，并且这两个键现在整个由 App 自己接管（`onKeyEvent` 永远
  返回 `true`），系统完全看不到原始按键事件，也就永远不会自己弹音量条：
  - 两个键在 `COMBO_WINDOW_MS`（目前 150ms）窗口内前后脚按下 → 识别成组合，直接触发
    捕获，两个键都不会真的改变音量，也不会有任何音量 UI；
  - 只按一个键 → 不会立刻生效，而是先等这个窗口过去，确认没有等到另一个键，才用
    `AudioManager.adjustSuggestedStreamVolume` 手动模拟一次系统默认的音量变化（含正常的
    音量条），效果和原生按键基本一样，只是会晚最多 150ms 才生效——正常调音量时基本感觉
    不出这点延迟；
  - 长按单键的自动重复不用等待，直接照常连续调音量。
  （早期版本这里有个 bug：识别组合后，抬起要不要吞是按"当前是不是组合状态"整体判断的，
  导致先按下、本该放行的那个键抬起也被吞掉，系统会以为它一直没松开，音量条卡住不消失。
  后来先改成"这个键自己的按下有没有被吞"来对称决定抬起，再后来干脆把两个键的原始事件
  全部接管，从根上不让系统看到——所以现在无论识别没识别成组合，都不会再有音量 UI 了。）
- 两个键之间允许的时间差（`COMBO_WINDOW_MS`，目前 150ms）是可调的：如果实测总是触发不
  了就调大，如果快速调音量时被误判成组合键就调小。
- 不要把两个键一起按住超过 3 秒——那是 Android 系统自己保留的「切换无障碍服务」手势，
  跟这个 App 无关，但物理按键是共享的。

## 权限说明

| 权限 | 用途 |
|---|---|
| 无障碍服务 | 监听音量组合键，并在触发时读取当前屏幕的文字节点（`canRetrieveWindowContent`），不截图、不录屏 |
| 网络 | 只连 `dashscope.aliyuncs.com`（阿里云百炼） |
| 通知（`POST_NOTIFICATIONS`） | 不发真正的通知，纯粹是因为 Android 13 起「后台 Toast」会跟着这个权限的开关状态走——没这个权限，触发/识别结果的提示会被系统直接静默吞掉，不报错、也看不出来 |

不再需要截屏（MediaProjection）权限、前台服务或常驻通知——状态栏没有录屏图标，
不触发的时候系统只在等按键事件，资源占用几乎为零。

## 首次使用

1. Android Studio 打开本项目，等 Gradle Sync（首次可能提示安装 SDK Platform 35，点确定即可）
2. USB 连接手机，点 Run
3. 打开 App：
   - 无障碍设置里开启「秒记」（会请求读取屏幕内容的权限）
   - 设置里填 API Key（bailian.console.aliyun.com 申请，支付宝/微信支付充值）、选一个保存文件夹
4. 切到任意 App，同时按一下音量上+音量下键：先感觉到两短震动、看到「已触发，识别中…」
   提示，稍等一下再等最终的识别结果反馈

## 已知限制

- 部分 App（如密码输入框、部分银行 App 的敏感页面）会把窗口标记为安全内容，无障碍服务读不到
  里面的文字，这类页面会读到空内容并提示"没读到屏幕上的文字"
- 无障碍服务被系统或用户关闭后需要重新手动开启
- 单独按一个音量键调音量时会有大约 200ms（`COMBO_WINDOW_MS` + 安全余量）的生效延迟（见上面
  「为什么是音量上+下键」一节），正常使用基本感知不到，这是为了让组合键触发时完全不弹音量
  条而做的取舍
- 两次按键如果没落在 `COMBO_WINDOW_MS`（目前 150ms）窗口内，会被当成两次独立的单键点按，
  那种情况音量条还是会正常出现、也不会触发捕获——这不是 bug，是没识别成组合时的正常兜底；
  如果实测经常按不准，把 `COMBO_WINDOW_MS` 调大一点即可
- 首次安装后如果拒绝了通知权限的弹窗，触发/识别结果的 Toast 提示可能不会显示（震动反馈不
  受影响）；可以去系统设置里手动把「秒记」的通知权限打开
